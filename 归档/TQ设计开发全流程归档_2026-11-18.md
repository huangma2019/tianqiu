## 1. 缘起与设计目标

TQ 的目标很明确：**不借助任何 UI 框架，从零写一个能用的桌面天球仪**。

最初的约束写在 `README.md` 第一段里——不依赖 Qt / MFC / WebView2 / OpenGL，只用 Windows 自带库（Win32 + GDI+ + WinHTTP + SQLite）。这决定了后续几乎所有设计取舍：

| 目标 | 落地方式 |
| --- | --- |
| 零外部依赖、绿色单 exe | 只用系统 DLL；SQLite 用官方 amalgamation 直接编进 exe |
| 天球必须“像球”而不是平面贴图 | 单位球 + 透视投影 + 3×3 旋转矩阵 + 背面剔除 |
| 数据要能长 | SQLite 持久化，内置精选数据保证离线可用，同时支持在线抓取与本地导入 |
| 交互要跟得上手 | 自研轨迹球旋转、鼠标锚点缩放、拖动 120ms 节流、像素级绘制预算 |
| 控件可复用 | `CelestialSphere` 独立窗口类，`TQSM_*` 消息 + `TQN_*` 通知，可嵌到别的工程 |

## 2. 技术选型与关键决策

| 决策点 | 选择 | 理由 / 代价 |
| --- | --- | --- |
| UI | 纯 Win32 自绘（GDI + GDI+） | 无框架可用；代价是标题栏、菜单、按钮、输入框、候选列表全部手写 |
| 绘图 | GDI+ 抗锯齿 + 自管 32bpp 像素缓冲 | GDI+ 支持 alpha / 路径；逐条调用的固定开销大，需要自建图层绕过 |
| 数据 | SQLite（amalgamation `sqlite3.c/h`，取自同机 ETF 工程，2025-02-18） | 免安装、单文件库、WAL 模式并发友好 |
| 压缩 | 自研 `tq_gzip.h`（DEFLATE 解码 + CRC32/ISIZE 校验） | Windows Compression API 不支持标准 GZIP，不能为解压引入 zlib |
| 网络 | WinHTTP（`catalog_download.cpp`） | 系统组件，支持重定向；后台线程 + 多源轮询 + 断点重试 |
| 行星/月球 | Meeus 月球理论（ELP-2000 截断）+ JPL 开普勒根数 | 精度足够，纯公式无星历文件 |
| 主题 | 深色 + DWM 未公开接口（`uxtheme` 序号 135/136） | 让系统菜单/滚动条跟随暗色，失败静默跳过 |
| 字体/缩放 | `SetProcessDPIAware` + 统一 `S(x)` 逻辑像素换算 | 只要一个缩放比，不处理 `WM_DPICHANGED`；跨屏交给系统拉伸 |

## 4. 天球控件的设计

### 4.1 几何与投影

- 世界坐标即赤道坐标（J2000），单位球；
- 相机相对球心的 3×3 旋转矩阵 `R_[3][3]` 累积（虚拟轨迹球，无万向锁）；
- **球外视角**：透视投影（相机距球心 3 倍球半径），剔除切点以外的背面球冠；
- **球心视角**（后期加入）：gnomonic 球心透视，朝 `-z` 看，剔除 `p.z >= 0` 的身后半天球；两种视角共用同一套旋转矩阵，`SetViewRA/GetViewRA` 自动按对面方向换算，Goto 动画在两种视角下都指向正确天区。

### 4.2 渲染管线（含性能专项）

原始实现每帧约 9000 次 `DrawLine`/`FillEllipse`，拖动明显卡顿。优化后（`README.md`“渲染性能”一节）形成固定管线：

1. **静态背景层**：球盘渐变、轮廓、刻度缓存为位图，逐行 `memcpy` 到主帧；
2. **路径合并**：网格 / 天赤道 / 黄道 / 银河 / 星座连线 / 深空标记按画笔并入 `GraphicsPath`，每类每帧只 `DrawPath` 一次，曲线采样放宽到 3°；
3. **恒星独立像素图层**：32bpp 内存缓冲直写，按球盘区域合成，不再逐颗调用 GDI+；
4. **输出**：`SetDIBitsToDevice` 直接推像素到窗口 DC，绕开 `Graphics::DrawImage` 的格式转换慢路径；
5. **节流**：拖动时主窗口刷新 120ms 节流、松手补发；主窗口按 `ps.rcPaint` 只重绘脏区；
6. **默认关闭抗锯齿描边**（工具栏“平滑”可开）。

压力测试结果：8 万颗星入库、2548 颗可见、1092×776 控件，稳态 **约 12 ms/帧（≈80 FPS）**。

### 4.3 天体与动态天象

- 恒星按视星等决定点径/亮度、按光谱型决定颜色，一等以上带光晕与星芒，标注带碰撞避让；
- 月亮：Meeus 月球理论（ELP-2000 截断）推算相位、照度、距离；
- 七颗行星：JPL 开普勒根数推算地心赤经赤纬，含一次光行时修正，视星等按相位角经验式；位置随时间框与自转实时更新；
- 地平层：地平圈、方位标记、天顶；观测者（经纬度 + 本地时间 + 方位角 35° 仰角）驱动定向；
- 自转：按真实恒星时速度 × 倍率推进本地时间。

### 4.4 交互设计

| 输入 | 行为 |
| --- | --- |
| 左键拖动 | 旋转天球（球心视角下为第一人称“转头”，输入取反） |
| 右键拖动 | 平移 |
| 滚轮 | 以鼠标位置为锚点缩放（球外 0.25–14x，球心 1–400x，不跨视角） |
| 单击 | 选中天体；贴图模式下星座优先于天体 |
| 双击 | 把该处天区平滑转到视图中心 |
| 方向键 / `+` `-` / `R` | 旋转 / 缩放 / 复位 |
| `G Q E B C J N L D P` | 网格、天赤道、黄道、银河、星座连线、边界、星座名、亮星标注、深空、行星 |

命中与通知：`PickObject()` 按像素距离与绘制半径判定，`starIndex` 用负数编码月球（-2）、行星（`-100-i`）、星座（`-1000-i`）；结果经 `WM_NOTIFY` 的 `TQN_HOVER / SELECT / VIEWCHANGED / DBLCLICK / RESET` 回传宿主。

### 4.5 复用接口

```cpp
tq::CelestialSphere::Register(hInst);
tq::CelestialSphere sphere;
sphere.Create(hwndParent, 0, 0, 800, 600, 1001, hInst);
sphere.SetData(catalogData);
sphere.Goto(5.6, -1.2);
```

消息族 `TQSM_RELOAD / SETOPTIONS / GETVIEW / SETVIEW / GOTO / RESET / GETSTATS / HIGHLIGHT / SETINSIDE / SETOBSERVER`，实现“控件化”，宿主与渲染彻底解耦。

## 5. 数据层设计

### 5.1 数据库（`tq_catalog.db`，WAL）

| 表 | 关键字段 | 用途 |
| --- | --- | --- |
| `stars` | `id, name, name_en, ra(小时), dec(度), mag, spectral, con, hip, source` | 恒星，`mag` 建索引 |
| `deepsky` | `id, name, kind, ra, dec, mag` | 深空天体 |
| `meta` | `k, v` | 应用元信息 |
| `const_art` | `abbr, style, layer, tone, counts, pts(float32 ra,dec)` | 星座贴图球面顶点（4 个灰度层） |
| `const_art_info` | `abbr, center_ra, center_dec, has_fill, has_outline` | 贴图索引 |
| `constellation_info` | `abbr, name_cn, name_lat, genitive, meaning, origin, myth, history, family, label_ra, label_dec` | 星座资料（信息卡数据源） |
| `constellation_boundary` | `abbr, ring, seq, ra_h, dec_d` | IAU 边界多边形（88 星座，Ser 两环） |

星座图案连线与 IAU 边界为**程序内置常量**，不入库；旧版 `constellations` 表在播种内置数据时清空。

### 5.2 城市库（`tq_cities.db`）

由 `中国行政区划经纬度_扁平版 副本.csv` 导入（取质心经纬度），`py` 列为名称拼音首字母（北京市 → `bjs`），供“地点”输入框按首字母过滤下拉；`Lookup()` 按名称精确查经纬度。

### 5.3 在线抓取

`sources.txt` 按书写顺序尝试，第一个成功即停止；同标签数据重复抓取先删旧再写新，不堆积：

| 源 | 内容 | 格式 |
| --- | --- | --- |
| Codeberg · HYG v4.4 | 119,614 颗 | `.csv.gz`，自动解压 |
| Codeberg · HYG v4.2 | 旧版备用 | `.csv.gz` |
| VizieR · BSC5 (V/50) | 9,110 颗耶鲁亮星 | TSV，`HH MM SS` |

解析器自动识别 CSV / VizieR TSV / gzip / 无表头四列文本，按列名匹配 `ra,dec,mag,proper,bayer,flam,con,spect,ci,hip,hr`；gzip 尾部校验失败自动重试一次再换源。导入时只保留 `-2.0 ≤ mag ≤ 9.0`。

## 6. 素材与数据管线（Python 工具链）

原始素材放在 `ziliao/`（499 个文件：255 SVG、191 PNG、17 PY、14 JSON、12 CSV），通过三个脚本转成程序可用的数据：

| 脚本 | 输入 | 输出 |
| --- | --- | --- |
| `tools_import_art.py` | `ziliao/constellation-db/constellation.db` | `const_art` / `const_art_info`（85 幅填充版贴图的球面顶点） |
| `tools_import_const_info.py` | `ziliao/88星座边界数据/*.csv` | `constellation_info`（缩写/拉丁名/所有格/含义/家族/文化根源/传说/出处） |
| `tools_make_icon.py` | 品牌图形参数 | `tq.ico`（多尺寸应用图标，见专项归档） |

数据库备份链也印证了管线顺序：`tq_catalog.db.bak`（2026-11-11，贴图导入前）→ `tq_catalog.db.pre_art`（同日，art 前的完整备份）→ 当前 `tq_catalog.db`（2026-11-17）。

星座贴图设计要点：每幅 4 个灰度层（`tone` 越大越亮），同层多段按 `FillModeAlternate` 合并（重叠处自动挖洞），投影后逐点成面，任意缩放下不失真；配色按星座下标循环取 8 种低饱和色调；相邻重叠或大倍率缩放时只取离视场中心最近的 18 幅，整帧设 12 万顶点预算。

## 11. 已知约束与后续方向

**约束**

1. 无版本控制：所有变更依赖文件时间与本文档记录，建议尽快 `git init` 纳入管理；
2. 系统缩放非整数 DPI 时，任何“位图缩放”都会失真——已有结论：标志类图形一律矢量绘制；
3. 星座贴图有 12 万顶点 / 18 幅的整帧预算，超大倍率下靠“最近视场中心优先”取舍；
4. 内置星表是演示级精选数据（J2000 近似坐标），精确数据需在线抓取或本地导入；
5. 信息卡宽度固定 372 逻辑像素，超长英文名可能需要自适应。

**方向**

1. 引入 git，把 `归档/` 与源码一起版本化；
2. 图标渲染与 `tools_make_icon.py` 参数（`RATIO` / `INNER` / `BLUE`）双向同步，避免两处配置漂移；
3. 星座信息卡按文本宽度自适应，并考虑加入“相关知识”折叠；
4. 若追求更高帧率，可把恒星图层改为直接写 DIB 段并做多线程分段渲染。
