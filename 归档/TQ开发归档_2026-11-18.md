## 1. 项目概述

TQ 是一个自建的 C++ 天球仪软件：球面投影渲染星空，支持星座/星表检索、城市与时间、在线星表下载，数据落 SQLite（`tq_catalog.db`、`tq_cities.db`）。

窗口为 `WS_POPUP` 无系统标题栏，标题栏与菜单栏合并成 32px 高的一条，全部由程序自绘（`DrawTitleBar`）。应用内还有两类关键自绘 UI：

- 天球控件 `celestial_sphere.cpp`：GDI+ 双缓冲 + 3D 球面投影；
- 星座信息卡 `g_info`：无激活的顶层透明窗口，经 `UpdateLayeredWindow` 合成，点击星座后弹出。

本阶段工作全部围绕“看得见的呈现问题”：信息卡被裁、品牌更名、图标从位图到矢量。

## 2. 阶段一：星座信息卡布局修复

### 2.1 问题现象

点击星座后弹出的信息卡（缩写 / 拉丁名 / 所有格 / 含义 / 家族 / 文化根源 / 传说 / 相关星座 / 来源注记）显示不完整：底部几行被窗口或屏幕边缘切掉，“传说”这类长文本折行后更是整段丢失。

### 2.2 根因

1. 高度只按“窗口客户区”估算，而高 DPI 小屏下窗口本身可能高于可用工作区；
2. 高度没有把多行字段的行数算进去；
3. 卡片以左上角为锚点向下生长，越靠下越容易被屏幕下沿截断；
4. 显示器矩形是物理像素、窗口坐标可能被系统虚拟化，两者尺度不一致时夹取失效。

### 2.3 解决方案

在 `ShowInfoCard()` 中改成“**双尺度夹取 + 底部锚定 + 行数计入**”：

```cpp
// main.cpp 约 1413-1452
int h = S(kCardHeadH) + (int)g_detail.size() * S(kCardRowH) + S(kCardFootH);

const int visRight  = min((int)wa.right,  (int)(wa.right  / g_dpiScale));
const int visBottom = min((int)wa.bottom, (int)(wa.bottom / g_dpiScale));
const int cardBottom = min((int)pb.y, visBottom - pad);
int cardLeft = min((int)px.x, visRight - w - pad);
cardLeft = max(cardLeft, (int)wa.left + pad);

const int roomBar  = cardBottom - max((int)pbar.y, (int)wa.top + pad);
const int roomFull = cardBottom - ((int)wa.top + pad);
if (h > roomBar) h = roomFull;
h = min(h, max(S(160), roomFull));

SetWindowPos(g_info, HWND_TOP, cardLeft, cardBottom - h, w, h,
             SWP_SHOWWINDOW | SWP_NOACTIVATE);
```

要点：

- **宽度**：`min(S(g_infoW)=372, max(S(220), 客户区宽 - S(40)))`；
- **双尺度**：`visRight/visBottom` 取“工作区物理值”与“工作区值 ÷ `g_dpiScale`”中更严的一个，规避坐标虚拟化差异；
- **底部锚定**：位置写成 `cardBottom - h`，卡片自下而上生长，天然不会被下沿截断；
- **高度策略**：优先只占工具栏以下区域；内容确实放不下时再向上占满整个工作区，下限 `S(160)`；
- 行高常量：`kCardHeadH = 48`、`kCardRowH = 27`、`kCardFootH = 38`。

### 2.4 收尾

- 移除了排查期间临时加入的 `_card.log` 调试日志（`_wfopen_s` / `fwprintf` 及 `#ifdef TQ_CARD_DEBUG` 分支），`SetWindowPos` 直接执行，无诊断分支；
- 实机点击“摩羯座”验证：缩写 `Cap`、拉丁名 `Capricornus`、所有格 `Capricorni`、含义、家族、文化根源、传说（潘 Pan / 提丰 Typhon，多行折行）、相关星座、来源注记全部完整显示；
- 清理临时脚本与截图（`_hover.ps1`、`_crop.ps1`、`_map.ps1`、`_c1.png`~`_c5.png` 等）。

### 3.2 图标资源体系（新增）

| 文件 | 作用 |

`build.bat` 关键片段：

```bat

cl /nologo /EHsc /std:c++17 /utf-8 /O2 /W3 ^
   /DUNICODE /D_UNICODE /DNOMINMAX /DSQLITE_THREADSAFE=0 ^

   ... /OUT:TQ.exe
```

`main.cpp` 侧：`WNDCLASSEXW` 的 `hIcon/hIconSm` 用 `LoadImageW(...IDI_TQ_APP...)`，建窗后 `WM_SETICON` 分别挂 `ICON_BIG` / `ICON_SMALL`，供任务栏与自绘标题栏共用。

### 3.3 图标设计迭代记录

素材：用户提供的深底星图 PNG（343×363 RGBA）。每次迭代都由 `tools_make_icon.py` 重新生成 `tq.ico`，再 `build.bat` 重编 exe。

| 版本 | 方案 | 结果 |

| v2 | 标题栏改圆形徽标：圆形裁剪 + 2.05× 提亮 + 1px 描边 | 轮廓有了，但整体过暗 |

| v4 | 亮度蒙版思路：暗底→蓝、线条→白（“蓝底白线条”） | 风格确定，缩到 16px 仍糊 |
| v5 | 改为矢量绘制的北斗七星（真实赤经赤纬投影，星等定大小，连线） | 七星位置正确，但小尺寸线条被抗锯齿冲淡 |

### 3.4 现行图标规格（`tools_make_icon.py`）

| 参数 | 值 | 含义 |
| --- | --- | --- |
| `RATIO` | `0.47` | 星芒外接半径 / 画布边长 |
| `INNER` | `0.235` | 内凹半径比例（越小星芒越细长） |
| `TILT` | `0.0` | 朝向，0 = 正十字 |
| `BLUE` | `RGB(58,150,255)` | 星体颜色 |
| `CORE` | `RGB(188,224,255)` | ≥64px 才加的浅色星芯 |
| 超采样 | 8× → LANCZOS | 边缘干净 |
| 输出尺寸 | 256/128/64/48/32/**28**/24/16 | 28 供标题栏 1:1 |

实现方式：8 点多边形（4 个尖 + 4 个内凹），透明底，无描边、无渐变。

## 4. 阶段三：标题栏星标模糊（DPI 根因与矢量化）

### 4.1 现象

桌面/资源管理器里的 `TQ.exe` 图标清晰，但程序内左上角星标呈块状发虚、边缘有明显阶梯。

### 4.2 根因

标题栏星标是**从 exe 内的位图放大**得来的：

1. 本机系统缩放非 100%，标题栏图标槽 `S(28)` 实际约 39 物理像素；
2. `tq.ico` 中最接近的帧只有 28px，`LoadImage` 把 28px 位图拉伸到 39px；
3. 再经 `Bitmap(HICON)` + GDI+ 双三次插值绘制，二次重采样 → 块状 + 发虚。

桌面图标之所以清晰，是因为资源管理器按自己需要的尺寸直接取合适帧，没有这一步放大。

### 4.3 修复：标题栏星标改为矢量现画

新增 `DrawStarGlyph()`，与 `tools_make_icon.py` 使用同一组几何参数，任何 DPI 下都是原生分辨率：

```cpp
// main.cpp 约 1186-1198
static void DrawStarGlyph(Graphics& g, REAL cx, REAL cy, REAL R) {
    PointF pts[8];
    for (int i = 0; i < 8; ++i) {
        const REAL a = (REAL)(-90.0 + i * 45.0) * 3.14159265358979f / 180.0f;
        const REAL rad = (i % 2 == 0) ? R : R * 0.235f;      // 四个尖 + 四个内凹
        pts[i] = PointF(cx + rad * cosf(a), cy + rad * sinf(a));
    }
    SolidBrush brush(Color(255, 58, 150, 255));
    g.FillPolygon(&brush, pts, 8);
}
```

`DrawTitleBar()` 中不再查询 `WM_GETICON`，直接按槽位中心绘制（`sz * 0.47f` 为半径），`SmoothingModeAntiAlias` + `PixelOffsetModeHalf`。

`tq.ico` 未受影响，桌面/任务栏/Alt-Tab 仍是原图标；两处共用参数，外观一致。

### 4.4 验证

- 1:1 抓取标题栏后放大 6 倍检查：边缘为平滑抗锯齿过渡，无阶梯块，四个尖完整；
- 从 `TQ.exe` 提取 32×32 图标：蓝色四芒星，清晰；
- 每次改动后 `build.bat` 均返回 `[OK] TQ.exe built.`，`main.cpp` 无 lint 诊断。

## 8. 经验与遗留

**经验**

1. **多尺度坐标要先归一**：物理像素与虚拟化坐标混用是“夹取失效”的常见根因，取两个尺度中更严的值最省事；
2. **图标别靠位图缩放**：非整数 DPI 下 `LoadImage` + GDI+ 二次重采样必然发虚，线条类标志直接矢量绘制；
3. **小尺寸优先保证形状可辨**：7 星、连线这类细节在 16px 下会互相吃掉，简化为单个四芒星反而更清楚；
4. **调试代码要及时撤**：`_card.log` 这类临时日志与 `#ifdef` 分支收尾时统一删除，构建脚本里也只保留一条主链路。

**遗留 / 可选**

- 资源管理器图标缓存刷新依赖系统，必要时手动重启 `explorer.exe`；
- 若将来再改品牌图形，建议只改 `tools_make_icon.py` + `DrawStarGlyph` 两处，并同步 28px 帧；
- 信息卡目前宽度固定 372 逻辑像素，若后续支持超长英文星座名，可考虑按文本宽度自适应。
